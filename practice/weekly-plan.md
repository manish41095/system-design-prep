# Weekly Preparation Plan

This plan fits alongside Java, Spring Boot, microservices and coding preparation. Use it as a flexible structure rather than a requirement to study every topic every day.

## Daily system-design session (60–90 minutes)

- 20–30 minutes: learn or revise one concept.
- 30–40 minutes: apply it to an HLD/LLD problem or write focused Java code.
- 10–20 minutes: explain without notes, answer follow-ups and update the tracker.

For a full timed mock, replace the normal design session rather than adding more hours. Take breaks and adjust the workload to your available time.

## Example first four weeks

| Week | Concepts | Main design | Practical exercise | Mock focus |
|---|---|---|---|---|
| 1 | Multi-tenancy, auth, DB isolation, caching | Multi-tenant SaaS | Two-tenant Spring Boot proof of concept | Tenant isolation and trade-offs |
| 2 | Estimation, load balancing, indexing, Redis | URL shortener + rate limiter | Token bucket / cache-aside | Estimation and bottlenecks |
| 3 | Kafka, outbox, idempotency, Saga | Notification + order system | Idempotent consumer or outbox | Reliability and consistency |
| 4 | Concurrency, locking, state machines, patterns | Vending machine + ticket booking | Java implementation and tests | LLD coding and concurrency |

After four weeks, use mock feedback to choose the next problems. Avoid moving to a new topic merely because a calendar says so.

## Weekly review

Record total focused sessions, concepts successfully recalled, designs completed, actual mock scores, recurring gaps and next week's three priorities. Re-attempt at least one weak design before starting several new ones. Track quality and understanding rather than GitHub contribution streaks.

## Interview-day revision

Review your two-minute introductions, strongest real-project examples, most common trade-offs, one HLD structure and one LLD structure. Avoid trying to learn an entirely new large topic immediately before an interview.
