# Weekly Preparation Plan

Multi-tenancy is deferred. Start with fundamentals and repeatable interview practice. This plan fits alongside Java, Spring Boot, microservices and coding preparation.

## Daily system-design session (60–90 minutes)

- 20–30 minutes: learn or revise one concept.
- 30–40 minutes: apply it to an HLD/LLD problem or write focused Java code.
- 10–20 minutes: explain without notes, answer follow-ups and update the tracker.

For a full timed mock, replace the normal design session rather than adding more hours. Take breaks and adjust the workload to your available time.

## First four weeks

| Week | Concepts | Main design | Practical exercise | Mock focus |
|---|---|---|---|---|
| 1 | Estimation, load balancing, indexing, caching | URL shortener | Base62 IDs, cache-aside, token bucket | Requirements and bottlenecks |
| 2 | Java concurrency, locks, state machines, SOLID | Vending machine + ticket booking | Java implementation and JUnit tests | LLD coding and concurrency |
| 3 | Kafka, outbox, idempotency, retries, DLQ | Notification + order system | Idempotent consumer or transactional outbox | Reliability and consistency |
| 4 | Replication, sharding, consistency, observability | Food delivery + media storage | Capacity estimates and failure recovery | Scaling and trade-offs |

After four weeks, choose the next problems from mock feedback. Do not move to a new topic merely because the calendar says so.

## Weekly review

Record focused sessions, concepts successfully recalled, designs completed, actual mock scores, recurring gaps and next week's three priorities. Re-attempt at least one weak design before starting several new ones. Track quality and understanding rather than GitHub contribution streaks.

## Interview-day revision

Review your two-minute introductions, strongest real-project examples, common trade-offs, one HLD structure and one LLD structure. Avoid learning an entirely new large topic immediately before an interview.
