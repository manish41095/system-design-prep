# First Seven Practice Sessions

This is a sequence of sessions, not seven mandatory consecutive days. Use 60–90 minutes per session. A full mock replaces the normal study session.

| Session | Focus | Work | Evidence to commit |
|---|---|---|---|
| 1 | Baseline HLD | Attempt [URL shortener mock 01](mock-01-url-shortener.md) for 45–60 minutes with no notes | Attempt, diagram, scorecard, top 3 gaps |
| 2 | Fix baseline gaps | Study only the three gaps found in session 1; explain each without notes | Three short concept notes and follow-up answers |
| 3 | Estimation + APIs | Do 10-minute estimation drills for URL shortener and notification system; design APIs and idempotency keys | Assumptions, calculations, API contracts |
| 4 | Cache + data | Add cache-aside, expiry, hot-key handling, schema/indexes and consistency choice to mock 01 | Revised diagram and decision log |
| 5 | Java LLD | Run a 60-minute vending-machine design: states, interfaces, change calculation, tests | Class diagram, Java code/tests, self-score |
| 6 | Full interviewer mock | Choose notification system or rate limiter from the [mock bank](mock-bank.md); ask one question at a time | Transcript, diagram, scorecard, re-attempt date |
| 7 | Review and re-solve | Review score trends and re-explain the weakest axis; re-solve one critical flow from memory | Weekly review and next three priorities |

## Rules

- Do not read a complete solution before the first attempt.
- Speak aloud and keep the timer visible.
- Preserve the original attempt; corrections belong in feedback or a second attempt.
- Score only evidence that exists.
- Convert each gap into a small exercise with a due date.
- Re-attempt weak designs after 7–14 days.
- Update concept/HLD/LLD confidence only after recall and follow-up questions.

## End-of-week review

Record:

- Number of focused sessions and full mocks.
- Score by each of the five axes, not only total score.
- Three repeated gaps.
- One improvement visible between attempts.
- Next week’s three priorities.
