## Progress rules

Use Not started, Learning, Can explain, Can apply, or Interview ready. Confidence is 0–5: 0 = unassessed; 1 = recognize; 2 = basics; 3 = internals and trade-offs; 4 = independently apply; 5 = defend under senior-level follow-ups. A topic is interview ready only after an explanation without notes, a practical application and successful follow-ups.

All new topics are unassessed. Prior exposure is not a verified score. Record production experience separately from study exercises. Never publish proprietary source code, customer information, credentials or internal architecture details.

## Interview structure

For HLD use requirements → scale → APIs → data model → architecture → critical flows → scaling/failures/security → trade-offs → summary. For LLD use requirements → entities → class diagram → patterns → interfaces → executable code → tests → concurrency/trade-offs. Always explain why a design choice is appropriate rather than naming technologies.

## Weekly workflow

Study concepts and apply them to a design during the week. Complete one timed 45–60 minute mock, record the top three gaps, revise them and re-attempt weak designs after 7–14 days. Update the tracker with evidence and the next action after each session.

## Priority

Multi-tenancy is a specific learning gap, not a claimed production skill. Build a tenant-aware SaaS design and explain isolation, authorization, persistence, caching and background jobs. Connect other concepts to genuine Java/Spring Boot backend experience where appropriate.
